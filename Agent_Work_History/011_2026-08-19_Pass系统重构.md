# Pass 系统重构开发记录（Phase 1 完成 + Phase 2 骨架设计）

## 日期
2026-08-19

## 背景
PBRRenderer 是巨型静态单例（`s_Data` 全局数据 + 所有渲染逻辑堆一个类），光源/阴影/主渲染耦合，GL 状态管理靠手动 bind + 手动恢复。目标是将渲染管线重构为「RenderContext + Pass 系统 + RenderGraph」的现代引擎结构。

---

## 一、完成内容

### Phase 1：RenderContext 拆分（已完成）

**目标**：把「每帧变化的输入数据」从全局 `s_Data` 中抽出，通过 `RenderContext` 显式传给渲染器。

**成果**：
- 新建 `struct RenderContext`（Camera / ViewportSize / Renderables / Lights / RenderTarget）
- `Render()` / `RenderShadowPass()` / `RenderPointShadowPass()` 全部改为接收 `RenderContext` 参数
- `AddLight(context, light, shadowIndex)` 全套迁到 context 版本
- `Register` / `SetCamera` / 无 context 的旧 `AddLight` / 旧 `Render()` 死代码全部删除
- `GetLightsCount(context)` 改为读 `context.Lights`（修掉了原来读 `s_Data.GPULights` 恒返回 0 的 bug）

**验证**：编译通过 + 功能不回归（多光源阴影、PBR、后处理正常）。

### Phase 2 骨架：Pass 系统（进行中）

**目标**：建立完整 Pass 系统（参考 UE5/Unity 架构）。

**已建文件**（`TheFoolEngine/src/TheFoolEngine/Renderer/`）：
- `Pass/Pass.h` — `RenderContext`（迁入）+ `Pass` 基类（`virtual Execute`）
- `RenderGraph.h` — 骨架（`AddPass`，待补 `Execute`/拓扑排序/资源池）
- `Pass/MainPass.h` — 主渲染 pass（待实现）
- `Pass/ShadowPass.h` — 方向光/聚光 + 点光源阴影 pass（待实现）
- `Pass/BloomExtractPass.h` — Bloom 提取 pass（待实现）

### 架构调研：UE5 / Unity 的做法

**UE5**：Pass 不是独立类，而是 `FSceneRenderer` 的成员函数，共享数据（`FScene`、`FSceneViewFamily`）天然可访问。RenderGraph（`FRDGBuilder`）用虚拟资源 + lambda 捕获自动推导依赖。

**Unity（URP）**：Pass 是独立 `ScriptableRenderPass`，通过 `Execute(context, renderingData)` 参数传递共享数据。URP 本质是顺序 pass 列表，HDRP 才更接近真 RenderGraph。

**核心共识**：
1. Pass 实现永远在引擎/渲染器层
2. 编辑器/游戏层只持有参数数据（VolumeProfile / PostProcessSettings）
3. 参数与 pass 解耦

### 架构决策（关键）

**决策：冲真 RenderGraph**（非 PassQueue）
- PassQueue 靠 vector 顺序执行、无显式依赖、无资源生命周期管理
- 真 RenderGraph 具备：虚拟资源 + 依赖声明 + 拓扑排序 + 资源池复用

**真 RenderGraph 四个能力与现状差距**：

| RenderGraph 能力 | 现状 | 差距 |
|---|---|---|
| 虚拟资源 | `Ref<FrameBuffer>` 直接持有 GL 对象 | 核心缺口 |
| 依赖声明 | 无 | 全新建 |
| 自动调度（拓扑排序）| 无 | 全新建 |
| 生命周期（资源池）| 手动 new FBO | 全新建 |

## 二、Step A 接口设计（已讨论，待实现）

**核心思想**：虚拟资源 = 纹理描述 + 池索引，FBO 是 pass 执行时的输出目标包装。

### `TextureDesc`（资源描述，纯数据）
```cpp
struct TextureDesc
{
    uint32_t Width = 0, Height = 0;
    TextureFormat Format = RGBA16F;
    uint32_t LayerCount = 1;
    uint32_t MipLevels = 1;
    uint32_t Samples = 1;
    bool IsDepth = false;
    bool IsCubemap = false;
    bool IsArray = false;
};
```

### `TextureHandle`（虚拟句柄，pass 持有）
```cpp
class TextureHandle
{
    TextureDesc Desc;
    uint32_t PoolIndex = 0;   // 指向 RenderGraph 资源池槽位
    std::string Name;          // 调试用
};
```

### `ResourcePool`（纹理池，核心）
```cpp
class ResourcePool
{
    uint32_t Allocate(const TextureDesc& desc);  // 同 desc 尽量复用
    void Release(uint32_t poolIndex);
    Ref<Texture2D> GetTexture(uint32_t poolIndex) const;
private:
    struct PoolEntry { TextureDesc Desc; Ref<Texture2D> Texture; bool InUse; };
    std::vector<PoolEntry> m_Pool;
};
```

### `Pass` / `RenderGraph`（改造）
```cpp
class Pass
{
    virtual std::vector<TextureHandle> GetOutputs() { return {}; }
    virtual std::vector<TextureHandle> GetInputs() { return {}; }
    virtual void Execute(RenderContext& context) = 0;
};

class RenderGraph
{
    TextureHandle CreateTexture(const TextureDesc& desc, const char* name);
    void AddPass(Scope<Pass> pass);
    void Execute(RenderContext& context);   // 拓扑排序→分配资源→执行→释放
};
```

### 待定设计点
1. **FBO 谁持有**：A. pass 内部创建（推荐，简单）；B. RenderGraph 生成（贴近 UE5，复杂）
2. **handle 解析**：A. context 里传池引用；B. Execute 前把池纹理塞进 pass

## 三、接下来的开发计划

### Step A：虚拟资源抽象（核心，先做）
- 建 `TextureDesc` + `TextureHandle` + `ResourcePool`（纯资源管理，不碰渲染）
- 只接 2 个资源验证：HDR 纹理、Bloom A 纹理
- `TestPass` 验证池复用（两帧间 GL 纹理 ID 不重复创建）
- **验证标准**：池复用生效

### Step B：依赖声明 + 拓扑排序
- pass 加 `SetInputs/SetOutputs`
- RenderGraph 收集依赖，DFS 拓扑排序

### Step C：自动生命周期
- Execute 里分配池资源 + 结束回收
- 支持 ping-pong（BloomA→BloomB→BloomA）

### Step D：收编现有 pass
- ShadowPass / PointShadowPass / MainPass / Bloom / ToneMap 改 RenderGraph 版
- EditorLayer 瘦身（只剩填 context + 参数）

### Phase 3：ShadowRenderer 拆分
- `SetShadowLight/SetSpotShadowLight/SetPointShadowLight` + 阴影数据从 PBRRenderer 抽出
- 方案 A：阴影数据暂留 `s_Data`（当前已选，先跑通骨架）

### Phase 4：s_Data 瘦身
- 只保留 Shader / DefaultTexture / Environment / State 等跨帧资源

### Phase 5：Scene 纯数据化
- Scene 只存光源/模型组件数据，渲染器每帧从 Scene 读取提交到 RenderContext
