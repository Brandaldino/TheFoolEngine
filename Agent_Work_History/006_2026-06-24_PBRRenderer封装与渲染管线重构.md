## 已完成

### 1. PBRRenderer 接口重设计
从旧 `BeginScene/EndScene/Submit` 演变为现代风格：

```
Init / Shutdown                          — 资源生命周期
ResetRendererState                       — 清帧状态 + 绑 fallback 纹理
Register(const PBRRenderProxy&)          — 注册渲染项
SetCamera(const CameraData&)             — 存相机数据
SetLight(const Light&)                   — 加一盏光源
Render()                                 — 统一绘制
ResetStats / GetStats                    — 调试统计
```

关键设计决定：
- `EndFrame` 删除（OpenGL 不需要 flush/unbind）
- 不再有 `defaultLight`，光源完全由调用方控制
- `CameraData` 结构体分离，`BeginFrame` 简化为无参 `ResetRendererState`

### 2. Light UBO 重构
去掉 4×N 次字符串 uniform 调用，改为一次 `glBufferSubData`：

```cpp
struct LightGPUBlock {
    glm::vec4 PositionType[10];     // xyz=pos, w=type
    glm::vec4 ColorIntensity[10];   // xyz=color, w=intensity
    int32_t LightCount;
};
```

Shader 侧对应：

```glsl
layout(std140, binding = 2) uniform LightBlock {
    vec4 u_LightPositionType[10];
    vec4 u_LightColorIntensity[10];
    int u_LightCount;
};
```

- PBRShader 淘汰旧的 `uniform Light u_Lights[10]` + `uniform int u_LightCount`
- for 循环内从 UBO 数组构造 Light 临时变量
- `struct Light { vec3; vec3; float; int; }` 保留作为局部类型定义

### 3. NodeTransform 修复
`ModelLoader.cpp` `ProcessNode` 读取 `node->mTransformation`：

```cpp
aiMatrix4x4 m = node->mTransformation;
meshes.back().NodeTransform = glm::transpose(glm::make_mat4(&m.a1));
```

`PBRRenderer::Render()` 中组合：`model = proxy.Transform * meshes[i].NodeTransform`

### 4. Sandbox_Model 迁移
- OnAttach：只 PBRRenderer::Init() + 创建 model + Import/UpLoad（不 Register）
- OnUpdate：每帧 ResetRendererState → Register(m_Proxy) → SetCamera → SetLight → Render
- .h 清理：删除 m_PBRShader、m_DefaultWhite/Normal/Gray/Black
- 删除 Renderer3D::ResetStats() 死调用

### 6. 排查 "渲染空白" 问题
现象：shader 编译成功，white output 测试无效，断点显示 OnAttach 时有模型数据但 Render 时没有。

**根因：** `OnAttach` 时 `Register(proxy)`，但 `ResetRendererState` 每帧清空 Renderables，导致 Render 时列表为空。数据只注册了一次就被清掉了。

**解决方案：** Sandbox_Model 持有一个 `m_Proxy` 成员，`OnUpdate` 每帧 `Register`。

## 架构演变总结

### 旧架构
```
Sandbox_Model 持有 shader + 纹理 + 渲染逻辑（70 行手写）
```
### 新架构
```
PBRRenderer 持有 shader + fallback 纹理 + 渲染逻辑
Sandbox_Model 只提供模型数据 + 相机 + 光源参数
```
### 下一步
```
PBRRenderer 持有 shader + fallback + UBO + 渲染逻辑
Scene ECS 持有模型/变换组件 → 自动填充 Renderables
Sandbox_Model / Editor 只选场景 + 调 Render
```

### 数据流演进
```
Phase 0（手工渲染）: Sandbox 直接调 OpenGL
Phase 1（本次）:     Sandbox → PBRRenderer API → OpenGL
Phase 2（ECS 集成）: Scene → PBRRenderer API → OpenGL
```

## 关键决策记录

| 决策 | 原因 |
|------|------|
| Light 用 UBO 而非单个 uniform | 4×N 次 API 调用 → 1 次，零字符串拼接 |
| `CameraData` 分离 | 不依赖具体 PerspectiveCamera 类型，支持多视口 |
| 每帧 Clear + 重 Register | 天然匹配 ECS 的"每帧遍历 Entity"，无需 Unregister |
| Fallback 在 ResetRendererState 绑 | 职责：设已知干净状态，而非 Init 时永久绑定 |
| 模型数据所有权在 Scene/Sandbox | Renderer 是"执行者"不是"数据容器"，解耦复用 |
