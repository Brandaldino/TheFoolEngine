# 合批系统开发记录（BatchBuilder + 实例化 + 模型缓存）

## 日期
2026-09-18

## 目标
向 UE5 看齐：用"排序（状态局部性）+ 实例化 + 缓存"替代逐 mesh draw call，降低 draw call 数。

对齐 UE5 的核心思路（不做静态顶点合批）：
- **排序**：按 shader → 材质 → 纹理 → VAO 排序，减少状态切换
- **实例化**：同 mesh + 同材质 → 一次 glDrawElementsInstanced
- **缓存**：模型缓存（同文件共享 VAO）——实例化的前提

## 设计

### BatchBuilder（合批器）
- `BatchKey`：VAO + IndexCount + 4 纹理 + 材质因子（指针级精确匹配，哈希+operator==）
- 同 key 的 mesh 合并为一个 Batch（Elements = 实例矩阵集合）
- `Sort()`：按纹理 → VAO 指针排序（状态局部性）
- 每帧重建（BatchBuilder 局部对象），结构上预留跨帧缓存路径

### 实例化（SSBO）
- 全局 SSBO（binding=1），每 batch 一段连续 range（实例矩阵）
- `glBindBufferRange` 按 batch 绑定 → shader 用 `u_InstanceModels[gl_InstanceID]`
- 每 batch `glDrawElementsInstanced`（实例数≥1 统一走实例化）

### 模型缓存（AsyncAssetLoader）
- `unordered_map<std::string, Ref<PBRModel>>`：path → 共享 Model
- 同文件复用 VAO → BatchKey 相同 → 可合批实例化

## 踩坑记录（重要教训）

### 1. BatchKey 双份 key 陷阱（最坑，导致实体全不渲染）
`unordered_map<BatchKey, Batch>` 里 key 存两份：
- **map 的 first**（key）：插入时拷贝传入 key（IndexCount=36）✓
- **Batch.Key**（second 的成员）：`Batch{}` 默认构造（IndexCount=0）——**从未被赋值！**

渲染循环读 `batch.Key.IndexCount` = 0 → `DrawIndexed(0)` → 不画任何东西。
**调试 2 小时才定位**：map 遍历 `[k, b]` 显示 `k.IndexCount=36`（对），但 `batch.Key.IndexCount=0`。
**教训**：`unordered_map<K, V>` 中 V 的"key 相关字段"是独立副本，插入时 V 默认构造，**必须显式同步**（`batch.Key = key`）。

### 2. vcxproj 路径 vs 磁盘路径（链接错误）
vcxproj 引用 `Renderer\BatchSystem\BatchBuilder.cpp`，磁盘在 `Importer\BatchSystem\` → 找不到 .cpp → 链接错误。
**教训**：移动文件后必须确认 vcxproj/filters 路径一致 + VS 重载项目 + Rebuild（清 Intermediate）。

### 3. DrawIndexed 里 glBindTexture(GL_TEXTURE_2D, 0)
每次 draw 后解绑当前 unit 纹理 → **破坏状态缓存**（curTex 认为纹理还绑着）→ 纹理错乱。
**教训**：底层 draw API 不该动纹理状态。

### 4. 路径归一化（同模型不合并）
场景 json 里同模型路径不一致（绝对 vs 相对）→ 缓存 key 不同 → 加载 2 个 Model → 不合并。
**修复**：`std::filesystem::weakly_canonical` 归一化缓存 key。
**场景保存也应统一绝对路径**。

### 5. null 纹理残留（状态缓存语义）
`PBRModel::SetBaseColor` 会置空 AlbedoMap/NormalMap → BatchKey 纹理为 null → 状态缓存 `if (key.X)` 不绑定 → **unit 残留上一 batch 纹理**。
**修复**：BatchBuilder 里 null → 默认纹理（`PBRRenderer::GetDefaultTexture`），BatchKey 永远非 null。

### 6. `auto` 拷贝默认纹理（性能 bug）
`auto prts = GetDefaultTexture()`（返回 const 引用）→ **深拷贝整个 PBRMaterialTextureSet（含 CPU 像素，几十 MB）**。
**修复**：`const auto& prts`。

### 7. HashUtils 语法 + float 哈希
- `std::hash<T>[] {}` 语法错误 → `std::hash<T>{}`
- `std::hash<float>` 对 NaN/-0.0 不稳定（-0.0 == 0.0 但 hash 不同）→ 违反 unordered_map 约定 → 需确保因子无 NaN
