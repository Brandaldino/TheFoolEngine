## 一、最终架构

### 序列化层（新增）
- `Scene/SceneSerializer.h/.cpp`：`Serialize(Scene*, path)` / `Deserialize(Ref<Scene>, path)`，JSON 文本格式（`dump(6)` 缩进）
- `Scene/JsonGlm.h`：`nlohmann::adl_serializer` 特化（glm::vec3/vec4/mat4 ↔ JSON 数组）
- `vendor/nlohmann/`：header-only 依赖（单头 `json.hpp`，无编译）

### JSON 结构
```json
{
  "Scene": {
    "Name": "...",
    "Environment": {},
    "Entities": [
      { "TagComponent": {...}, "TransformComponent": {...},
        "LightComponent": {...}, "PBRModelComponent": {...},
        "SpriteRendererComponent": {...}, "CameraComponent": {...} }
    ]
  }
}
```
- 组件名做 key，**存在才序列化**（缺失字段反序列化时 `contains()` 判断）
- PBRModel 只存 `FilePath`（UE5 路径引用思想），加载时重新 `Import + DefaultTextureFill + UpLoad`

### 依赖改动
- `Scene.h`：`friend class SceneSerializer;`
- `SceneCamera.h`：补 `GetPerspectiveNear/Far`、`GetOrthographicNear/Far` getter
- `Entity.h`：加 `IsValid()`（`m_Registry.valid(handle)`）
- `premake5.lua`：nlohmann include + `OFN_NOCHANGEDIR`（见坑）
- EditorLayer：File 菜单 Save/Load + `m_ScenePath`；ImportModel/ImportSkybox 加 `OFN_NOCHANGEDIR`

## 二、关键坑及解决

| # | 现象 | 根因 | 解决 |
|---|------|------|------|
| 1 | `nlohmann/json.hpp` 找不到 | include 目录 = `vendor/nlohmann`，但 include 写 `nlohmann/json.hpp`（多一层） | include 目录指向 `vendor` 根 或 include 去掉前缀 |
| 2 | vcxproj 不含 nlohmann | premake 改了但没重新生成项目 | 改 premake 后必须跑 `Win-GenProjects.bat`，别手改 vcxproj |
| 3 | `static assertion 'Ill-formed request'` | enum class 直接赋给 json | `static_cast<int>` |
| 4 | `adl_serializer` 不是模板 | 特化写在 `TheFoolEngine` 命名空间内 | 必须直接在 `namespace nlohmann` 内特化 |
| 5 | adl_serializer 不解决隐式转换 | 它只提供 `.get<T>()` 显式转换，glm 类型不能隐式转 | 反序列化必须 `.get<glm::mat4>()` 等 |
| 6 | "Entity already has component" 断言 | `Scene::CreateEntity` 默认加 Transform+Tag，反序列化重复 AddComponent | Transform 用 `GetComponent` 修改，不重复添加 |
| 7 | 加载后选中/持有实体崩溃 | `m_Registry.clear()` 使外部 Entity 引用失效（handle 悬空） | `Entity::IsValid()` + 用前检查；加载后清空选中 |
| 8 | import 模型后保存/加载失效（"Scene file does not exist"） | **`GetOpenFileNameW` 默认改变 CWD**，后续相对路径全失效 | `ofn.Flags` 加 `OFN_NOCHANGEDIR` |
| 9 | `parse_error` 未处理崩溃 | `Json::parse(in)` 无 try/catch | 加 try/catch + `exists()`/`open` 检查 |
| 10 | InnerAngle 写两次、OuterAngle 丢失 | 复制粘贴笔误 | 逐字段校对 |

## 五、经验教训

1. **相对路径是脆弱的**：CWD 一变（文件对话框！）所有相对资源路径失效。长期应基于 exe 定位资源根（`Application::GetAssetsDirectory`），不依赖 CWD。
2. **序列化存"引用"而非"内容"**：PBRModel 存路径（对齐 UE5 FSoftObjectPath），加载重建——正确。但**模型运行时修改**（SetBaseColor）要存"覆盖状态"才能持久化。
3. **ECS 实体 handle 会失效**：`clear()`/重建后外部持有的 Entity 悬空，`IsValid()` 是标准防护。
4. **premake 是唯一源**：手改 vcxproj 会被下次生成冲掉；改 premake5.lua 后必须重新生成。
5. **nlohmann 的扩展点**：`adl_serializer` 在 `nlohmann` 命名空间特化，提供显式 `.get`；enum 要 `static_cast`。
