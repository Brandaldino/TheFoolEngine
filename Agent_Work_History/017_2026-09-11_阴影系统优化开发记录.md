# 阴影系统优化开发记录（CastShadow / 分辨率 / 预算 / 缓存）

## 日期
2026-09-11

## 背景
视锥剔除完成（016 日志）后，用压力测试（102 个模型网格散布，共享同一 PBRModel）验证性能，用 Instrumentor 抓一帧耗时，发现**阴影是压倒性瓶颈**。

## 一、压测数据（一帧耗时，约 38ms @ 20fps）

| Pass | 耗时 | 占比 |
|------|------|------|
| PointShadowPass | 16.3ms | 43% ← 最大头 |
| MainPass | 11.0ms | 29% |
| ShadowPass | 8.9ms | 23% |
| 后处理（Extract/Blur/Combine/ToneMapping） | ~2ms | 5% |

**阴影合计 25ms = 66%**。后处理不是问题。

### 根因
- 点光阴影：2 个点光 × 6 面 = 12 次场景重画，全部 ShadowCasters
- 所有灯光无差别开阴影 + 固定 1024 分辨率 + 每帧全量重画（无缓存）
- MainPass 11ms 为 CPU 提交瓶颈（uniform/纹理绑定/每 mesh 状态切换）

## 二、决定范围（本次只做这 4 项）

对齐 UE5 阴影哲学（阴影是稀缺预算，不是默认功能）：

1. **开关（CastShadow）**：`LightComponent` 加 `CastShadow` 标志，不是所有灯开阴影
2. **分辨率（Shadow Resolution）**：阴影图分辨率可配置/按灯光类型默认（点光 512、方向光 1024），而不是全固定 1024
3. **预算丢弃（Budget）**：阴影有预算上限，超过优先级的阴影被丢弃（该灯变无阴影但渲染正常）——对齐 UE5 `ProjectedShadowInfo` 优先级 + 预算
4. **可缓存（Static Cache）**：静态模型阴影可缓存，不每帧重画（对齐 UE5 静态/动态分离）

## 三、明确不做（后续）

- **CSM 级联阴影**（方向光分层）——大工程，后续单独做
- **Lumen / 光追阴影**——另一个量级
- **后处理优化**——压测显示后处理只占 5%，非瓶颈

## 四、UE5 参考要点

- `Cast Shadows` 是光源显式开关
- 阴影分辨率按 `ResolutionKey` 按需（256-2048），点光常用 256
- `ProjectedShadowInfo` 优先级 + `FSceneRenderer` 预算分配，超预算丢弃
- 静态物体阴影可缓存（`bRenderStaticSceneShadow`），动态才每帧更新
- CSM：方向光按距离分 3-4 级联，近清晰远覆盖

## 六、PBRShader.glsl 阴影累积 bug（重要发现）

- **现象**：阴影灯越多整体越暗（不是局部暗部，而是全局越乘越暗）
- **根因**：`Lo *= (1.0 - shadow)` 写在灯光 for 循环内，乘的是**所有已累积的光照**而非当前灯贡献：
  ```glsl
  Lo += 当前灯贡献;
  Lo *= (1.0 - shadow);   // ← 把前面所有灯的贡献也乘暗
  ```
  每多一个带阴影光源，前面所有灯（含无阴影的）贡献被反复乘暗
- **修复**：阴影只乘当前灯贡献：
  ```glsl
  vec3 contribution = (diffuseBRDF + specularBRDF) * radiance * NdotL;
  if (ShadowIndex >= 0) contribution *= (1.0 - shadow);
  Lo += contribution;
  ```
- **物理 vs bug 区分**：阴影本质 = 光线的可见性测试（遮挡制造暗部，正确）；累积相乘 bug = 数学错误（全局越乘越暗，错误）
