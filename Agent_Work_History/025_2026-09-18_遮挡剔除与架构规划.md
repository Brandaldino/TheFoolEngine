## 一、遮挡剔除（完成）

### 目标
视锥剔除后的第二层剔除：**视野内但被其他物体完全挡住**的实体不渲染。对齐 UE5 的 Primitive Visibility 分层状态机。

### 实现（三个模块 + 一个 shader）
- **OcclusionQuery**：GL_ANY_SAMPLES_PASSED 硬件遮挡查询（包围盒有像素通过深度测试 → 可见）
- **OcclusionManager**：UE5 分层状态机
  - Visible（渲染 + 每帧测）/ RecentlyOccluded（不渲染 + 每 8 帧测）/ Occluded（不渲染 + 每 30 帧测）
  - **渐进降级**（可见→最近遮挡→深遮挡）+ **直接升级**（遮挡→可见立即恢复）——防闪烁
  - `entt::to_integral(entity)` 做键 + Prune 清理失效实体
- **OcclusionPass**：MainPass 渲染后（深度就绪）提交包围盒查询，专用 OcclusionShader
- **EditorLayer**：视锥剔除后 → 遮挡过滤（IsVisible）→ 进 Renderables

### 查询延迟一帧
查询结果下帧使用（读上一帧查询）——无 GPU stall，UE5 同款思路。

### 踩坑（重要）
1. **OcclusionQuery 隐式拷贝 → GL 资源双份共享**：Query 有自定义析构（glDeleteQueries），编译器不生成移动构造 → map 扩容用拷贝 → 两个 entry 共享同一 GL query → 一个析构删除、另一个悬空 → 崩溃。
   **修复**：改用 `Scope<OcclusionQuery>`（unique_ptr，移动转移指针）+ 显式禁拷贝
2. **空 shared_ptr 解引用崩溃（地址 0x10）**：`m_Occlusion`（Ref）构造时没 CreateRef → 空指针 → `m_Occlusion->ReadBackResults()` 通过 nullptr 访问成员（this 偏移 0x10）→ 崩溃地址 0x10 吻合。
   **教训**：nullptr 调成员函数"碰巧"不崩的前提是不访问 this 成员——首个访问就崩
3. **`==` vs `=`**：状态降级写成了 `entry.State == OcclusionState::Occluded`（比较而非赋值）——降级永不生效

### 验证
- 视锥内 + 被大模型完全挡住 → 不渲染（draw call/渲染实体数下降）
- 转视角露出 → RecentlyOccluded 重测 → 恢复渲染（无闪烁）
- **注意**：合批后 draw call 粒度是 batch，部分遮挡时 draw call 不变（可见实例仍合批）——收益看实例数/GPU 时间

## 二、架构规划（新增，入 ROADMAP）

### 规划 1：全局 UID 系统
- 所有实体加入 uid，扩展为**整个引擎所有资产统一 uid**
- 动机：遮挡剔除用 entt::to_integral 做键（实体销毁重建 index 复用，不稳定）；序列化引用/资源管理/调试需稳定 ID
- 设计：IDComponent（uint64）+ 资产注册表（AssetRegistry），对齐 UE5 UObject/FName

### 规划 2：跨图形 API 抽象（RHI）
- 消除绕过抽象层直接调用 OpenGL 的代码（SSBO、OcclusionQuery、DSA 调用等）
- RHI 抽象层：Buffer/VAO/Texture/Shader/Query/SSBO 全走抽象接口，GL 实现收进 Platform/OpenGL
- 对齐 UE5 RHI（RHIResource/RHICmdList）
