# UID 系统开发记录（规划 1：Step 1 实体 UID）

## 日期
2026-09-18

## 目标
为实体加入唯一 ID（UID），后续扩展为整个引擎所有资产（模型/纹理/材质）统一 UID。对齐 UE5 的 `UObject` + 资产注册表思路。

**动机**：
- 遮挡剔除键用 `entt::to_integral(entity)`（32 位）——实体销毁重建后 entt index 复用（版本号缓解但不绝对稳定）
- 序列化引用、资源管理、调试、网络同步都需要稳定 ID

## 实现

### 1. Core/UUID.h
```cpp
using UUID = uint64_t;

inline UUID GenerateUUID()
{
    static std::mt19937_64 rng{ std::random_device{}() };
    return rng();
}
```
**随机生成**（非自增）：多线程/场景合并不碰撞，64 位碰撞概率极低（UE5 用随机 GUID）。

### 2. IDComponent（Components.h）
```cpp
struct IDComponent
{
    UUID ID;
    IDComponent() : ID(GenerateUUID()) {}           // 默认生成
    IDComponent(const UUID& id) : ID(id) {}         // 反序列化用
};
```

### 3. Scene::CreateEntity 自动加 IDComponent
运行时新建实体自动获得 UID。

### 4. SceneSerializer 保留 UID
- **序列化**：`entityJson["IDComponent"]["ID"] = entity.Get...ID`
- **反序列化**：json 有 UID → **覆盖**（GetComponent().ID = jsonID）；无（旧场景）→ 保留 CreateEntity 生成的

### 5. OcclusionManager 键迁移
`entt::to_integral`（uint32）→ `UUID`（uint64）：
```cpp
std::unordered_map<UUID, OcclusionEntry> m_Entries;
void UpdateEntity(UUID id, ...);
```
实体销毁重建不冲突，**UID 绝对稳定**。

## 踩坑（重要）

1. **重复组件**：`CreateEntity` 已 `AddComponent<IDComponent>()`，反序列化再 AddComponent → 重复组件。
   **修复**：反序列化用**覆盖**（GetComponent().ID = jsonID），不 AddComponent
2. **entt view 不含组件**：`view<TagComponent>()` 里 `view.get<IDComponent>` 报错——view 只含声明组件。
   **修复**：view 声明加 `IDComponent`（`view<TagComponent, IDComponent>()`）
3. **get 返回组件引用**：`view.get<IDComponent>(entity)` 返回 `IDComponent&`，不能赋给 `UUID`——要取 `.ID`。
   **教训**：entt 的 get 返回组件引用，取成员要显式
4. **类型迁移遗漏**：改 `m_Entries` 键类型时，误改了 `GetTestInterval` 返回类型（→ UUID，应 uint32）和 `GetEntitiesToTest` 返回类型（vector<uint32_t> vs m_TestCandidates vector<UUID>）——**声明/实现/容器类型要一起改**
5. **activeIDs 类型**：EditorLayer 的 `unordered_set<uint32_t>` 插 UUID（uint64）→ 截断。应 `unordered_set<UUID>`

## 验证
- 场景加载/保存：UID 保留（json 有 ID，重载一致）
- 遮挡剔除：键用 UUID，实体销毁重建不冲突
- 旧场景 json（无 IDComponent）→ 生成新 UID（兼容）
