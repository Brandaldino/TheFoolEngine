# 阴影数据流统一与 RenderGraph 资源池化开发记录

## 日期
2026-09-04

## 目标
将阴影系统彻底收敛到 RenderGraph 体系：GPU 阴影图走 transient 池化（对齐 UE5 RDG），CPU 阴影数据统一进 RenderContext（scene 一次推导、多 pass 共享），ShadowRenderer 逐步瘦身为纯执行者直至消亡。

---

## 一、最终架构（本次达成）

### 资源管理（RenderGraph 单一资源体系）
- `m_Resources` 统一资源表（`RenderTargetResource`：Desc / FrameBuffer / PointShadowMap / IsTransient / PoolIndex）
- `TransientResourcePool`：GPU 对象池化，帧末回收跨帧复用
- **更纯的资源声明**：`CreateRenderTarget` 对 transient 只建条目（`PoolIndex = UINT32_MAX`），每帧声明阶段按 desc 分配池槽（同 desc 共享池槽），帧末 `ResetFrame()` 放回 FreeList

### 数据流（RenderContext 唯一数据源）
```
Scene → context（Lights + ShadowViewProjections + PointShadow，一次推导）
              │
   ┌──────────┼────────────┐
   ▼          ▼            ▼
ShadowPass  PointShadowPass  MainPass（共享 context，不重复计算）
```
- `ShadowMath`（inline 头文件工具）：方向光/聚光/点光阴影矩阵纯函数，无状态
- 阴影 handle 由 EditorLayer 通过 `RenderGraph::CreateRenderTarget` 声明，ShadowRenderer 不再持有资源

### pass 依赖链（补全）
- ShadowPass out = DirectionalShadow / PointShadowPass out = PointShadow / MainPass in = {方向光, 点光}
- 拓扑排序 RAW 依赖保证 ShadowPass / PointShadowPass 严格先于 MainPass（不再靠 AddPass 顺序侥幸）

### ShadowRenderer（过渡，纯执行者）
- 仅剩：shader 资源 / Light UBO / AddXxxLight（打包 GPULight 填 context）/ SetGPULightFBO（UBO 提交）
- 无数据、无资源句柄 → 下一步消亡

## 二、关键改动

### Step 1：阴影数据进 context
- RenderContext 增加 `ShadowViewProjections`（方向/聚光 VP）+ `PointShadow`（点光数据）
- EditorLayer 提交灯光时一次算完矩阵进 context（`ShadowMath::ComputeDirLightVP` 等）
- ShadowPass / PointShadowPass / MainPass 改读 context（删 ShadowRenderer 的 GetViewProjections / GetPointShadowData）

### Step 2：handle 上移 + 依赖链补全
- EditorLayer 用 `CreateRenderTarget` 声明 `m_ShadowFBOHandle` / `m_PointShadowHandle`
- ShadowRenderer 删 handle 成员
- PointShadowPass 增加 SetOutput / GetOutputs（此前无输出声明 → 点光阴影无 pass 依赖）
- MainPass 增加 `SetInputPointShadow`，GetInputs 返回两个输入

### 清理
- PBRRenderer light API 全部删除（AddLight×6 / GetLightsCount / GetLightUBO / LightUBO）——顺带解决与 ShadowRenderer UBO 的 binding=2 冲突
- ShadowTypes 注释字段清理
- pass SetInput / SetOutput 签名统一（值参数）
- ShadowRenderer::Init 去 graph 参数

## 五、架构愿景（对齐 UE5 的思考）

### 目标分层
```
Scene → RenderContext（跨帧数据，生命周期与 scene 挂钩）
ResourcePool（长期/静态共享资源，进程生命周期）
临时资源（转交 RenderGraph，帧级）
RenderGraph（纯逻辑：组织 pass 执行）
  pass = 渲染数据(context) + shader 数据(ShaderSystem)，不持有数据性资源
  pass 依赖链（参考 job system 多线程设计，可定制化）
帧队列 → 交换链（决定下一帧替换/丢弃帧）
```

### UE5 对标要点
- **Scene 与 Renderer 分离**：UE5 的 FScene（渲染场景）与 UWorld 分离，通过 AddPrimitive / UpdateTransform 命令同步。RenderContext 定位应区分"每帧提交数据"与"跨帧渲染状态"
- **资源分层**：磁盘资产（UObject）→ 加载资源（FRHITexture / Buffer）→ 渲染资源（FRenderResource，RenderThread 创建/销毁）
- **命令队列**：FRHICommandListImmediate 录制命令 + RHIThread 消费；状态缓存避免冗余切换 + draw call 按状态/材质排序
- **帧节奏**：Present 模式（FIFO / MAILBOX / IMMEDIATE）+ 多帧在途（in-flight）+ FramePacer
- **Shader 系统**：编译产物 + 反射（uniform 反射），跨材质共享 FShaderMapResource

### 运行时资源管理问题（待深入）
- 运存：资产引用计数 + 卸载策略；纹理 Mip 流送（只加载需要的 mip 级别）
- 显存：GPU 纹理池 + 上传队列（staging buffer）；持久 vs 临时 heap 划分
- 命令队列：避免频繁 flush、批量提交、状态缓存减少冗余切换
