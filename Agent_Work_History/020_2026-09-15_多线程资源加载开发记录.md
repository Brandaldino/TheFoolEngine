# 多线程资源加载开发记录

## 日期
2026-09-15

## 目标
将 CPU 密集的资源加载（模型解析、纹理解码、文件读取）从主线程移到后台线程，避免加载卡顿；GL 资源上传保持在主线程。

## 核心约束（最重要）

**OpenGL 上下文单线程**：GL 资源创建（glCreateTexture/VAO/VBO/IBO）**只能在主线程**。

因此加载分两段：
```
后台线程：CPU 密集（Assimp 解析、stb_image 解码、文件读取）→ 无 GL
主线程：   GPU 上传（创建 GL 资源）+ 资源注册 + 回调
```

## 现有基础设施

- **JobSystem**（`Core/Job/`）：Submit / SubmitWithDeps / ParallelFor / Wait / 线程池 —— 已初始化（Application）
- **moodycamel::ConcurrentQueue**（vendor/moodycamel）：后台→主线程完成队列可用

## 设计

### AsyncAssetLoader（或并入 AssetManager 雏形）

```cpp
struct AsyncLoadResult {
    std::string Path;
    Ref<PBRModel> Model;
    std::function<void(Ref<PBRModel>)> Callback;   // 主线程回调
};

class AsyncAssetLoader {
public:
    void LoadModelAsync(const std::string& path, std::function<void(Ref<PBRModel>)> callback);
    void ProcessCompleted();   // 主线程每帧调用
private:
    moodycamel::ConcurrentQueue<AsyncLoadResult> m_Completed;
};
```

### 流程
```cpp
void LoadModelAsync(path, callback)
{
    JobSystem::Get().Submit([this, path, callback] {
        auto model = CreateRef<PBRModel>();
        model->Import(path);              // 后台：Assimp 解析 + 纹理解码（无 GL）
        m_Completed.enqueue({ path, model, callback });
    });
}

void ProcessCompleted()   // 主线程，OnUpdate 每帧
{
    AsyncLoadResult result;
    while (m_Completed.try_dequeue(result))
    {
        result.Model->UpLoad();          // 主线程：GL 上传
        result.Callback(result.Model);
    }
}
```

## 实施切入点

1. `EditorLayer::ImportModel`：`Import` 异步化（对话框后 LoadModelAsync，回调里加组件）
2. `SceneSerializer::Deserialize`：模型重建异步化（先建实体，加载完挂组件）
3. 启动场景加载（如多模型场景）

## 风险 / 注意

- **PBRModel 线程安全**：`Import` 只写 `m_ModelData`，无 GL —— 后台安全；`UpLoad` 主线程
- **纹理**：Assimp 纹理解码（stb_image）在 Import 内（后台）；纹理 GL 上传需确认在哪（若在 UpLoad 则主线程 OK）
- **回调时机**：主线程 ProcessCompleted 里回调，避免跨线程触碰 GL/registry
- **ShaderLibrary**：已预编译（无运行时加载）；shader 异步编译后续（对齐 SCW）

## 关键发现：纹理 GL 上传混在 Import 里（阻塞后台化）

`ModelLoader.cpp` 的 `LoadTexture`：
```cpp
unsigned char* data = stbi_load_from_memory(...);   // CPU 解码
...
return Texture2D::Create(w, h);                     // ← GL 创建 + 上传！
return Texture2D::Create(fullPath);                 // ← GL！
```

**`Texture2D::Create` 是 GL 调用（glGenTextures/glTexImage2D），在 `PBRModel::Import` 路径里** → 后台线程做 Import 会触碰 GL → 崩溃。

### 必须拆分：CPU 解码 vs GL 上传
```
后台：Assimp 解析（顶点/索引）+ stbi 解码（像素数据）→ 存 CPU 缓冲
主线程：Texture2D 从 CPU 数据创建（GL）+ 网格 VAO 创建（UpLoad）
```

### 拆分方案
1. `LoadTexture` 改为返回 **CPU 像素数据**（不创建 GL 纹理）：`stbi_load` 结果存 `TextureData{ w, h, std::vector<unsigned char> }`
2. `PBRMaterialTextureSet` 或中间结构存 CPU 纹理数据（替代 `Ref<Texture2D>` 直到上传）
3. `UpLoad`（主线程）：从 CPU 数据创建 `Texture2D`（GL）+ 网格 VAO
4. 需要 `Texture2D` 支持"从 CPU 像素创建"（SetData 已有，或加 Create(w,h,data)）

### 现状结论
- 当前 `Import`（含纹理 GL）**不能直接后台化**，需先拆分纹理加载
- 拆分后：后台 Import（解析+解码）→ 主线程 UpLoad（纹理+网格 GL）→ 完整多线程加载成立

## 坑记录

1. **lambda 按引用捕获局部变量**：`ImportModel` 回调用 `[&]` 捕获 `filepath` → ImportModel 返回后悬空 → `path.stem()` 断言崩溃。**修复**：回调签名带 `path` 参数，用 `result.Path`（队列显式传递），不捕获局部。
2. **回调签名不一致**：`AsyncLoadResult::Callback` 忘改带 path → 编译错。统一用 `LoadCallback`。
3. **ProcessMaterial 未切 DecodeTextureCPU**：旧 `LoadTexture`（GL）还在填 `AlbedoMap`，`AlbedoCPU` 空 → 上传空 → 补默认白 → 颜色丢失。**修复**：ProcessMaterial 改填 `XXXCPU` 字段，删旧 LoadTexture。
4. **函数定义顺序**：`DecodeTextureCPU` 在 `ProcessMaterial` 之后 → 找不到标识符。前向声明或调整顺序。
5. **SetBaseColor 时序**：`UpLoad`（上传纹理）在 `SetBaseColor`（清纹理）之后 → 覆盖纯色 → ground 恢复贴图色。**修复**：SetBaseColor 在 UpLoad/DefaultTextureFill 之后。

## 多线程加载原则

- **GL 只能在主线程**：后台只做 CPU 解析/解码，主线程上传
- **跨线程数据走队列显式传递**（result.Path），不靠 lambda 捕获局部变量
- 回调（主线程）里才能碰 GL/registry
