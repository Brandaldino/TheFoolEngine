# 动态 Pass 开发记录

## 日期
2026-09-15

## 目标
将渲染 pass 图从"静态构建（OnAttach 一次）"演化为**可定制/可选 pass**：运行时可配置启用哪些 pass（如 Bloom 开关）、按场景需要增减 pass，依赖链动态推导。

## 现状

- `RenderGraph`：`AddPass(Scope<Pass>)` 在 OnAttach 调用一次，`m_Passes` 静态
- `Execute`：声明阶段（transient 分配）→ 拓扑排序（RAW/WAW）→ 顺序执行 → ResetFrame
- 资源 handle（HDR/LDR/Bloom×3/阴影）在 OnAttach 通过 `CreateRenderTarget` 声明
- 所有 pass 固定启用（Main/Shadow/PointShadow/BloomExtract/BloomBlur×2/BloomCombine/ToneMapping）

## 设计方向（渐进）

### 1. 轻量：运行时增删 pass
- `RenderGraph::RemovePass(name)` / `AddPass` 支持运行时调用
- 依赖链动态推导（拓扑排序已有，自动适应）
- 场景：Bloom 关闭时移除 BloomExtract/Blur/Combine，保留 ToneMapping

### 2. 配置驱动：PassPipeline（推荐形态）
- 一个**管线配置**决定启用哪些 pass：
  ```cpp
  struct PassPipelineConfig {
      bool EnableBloom = true;
      bool EnableShadows = true;
      bool EnableToneMapping = true;
      // ...
  };
  ```
- `RenderGraph::Build(config)`：按配置 AddPass
- 配置变化（运行时）→ 重建 pass 图（清空 + 按配置重建）
- 资源 handle 生命周期：Bloom 关 → BloomA/B/C 资源不创建（省显存）

### 3. 完整：每帧重建 pass 图（对齐 UE5 RDG）
- UE5 `FRDGBuilder` 每帧构建：pass 用 lambda 注册，资源声明 + 依赖动态推导
- 当前引擎静态图 + 每帧数据流（RenderContext）已经接近，但 pass 结构固定
- 完整动态：pass 数量和顺序每帧可变（如根据可见光源数量决定阴影 pass 数量）

## 对齐 UE5

- UE5 RDG：`GraphBuilder.AddPass(name, params, lambda)` 每帧构建，资源虚拟化 + transient 池化
- pass 依赖由**资源访问声明**推导（我们已有：GetInputs/GetOutputs → 拓扑排序）
- 动态程度：UE5 每帧重建；当前引擎静态图 → 先做"配置驱动重建"，再做"每帧重建"

## 实施顺序

1. ✅ `RenderGraph::ClearPasses` + `PassPipelineConfig` + `BuildRenderGraph(config)`（配置驱动重建）
2. ✅ EditorLayer 接入：Bloom/Shadows 开关（UI + dirty 标记重建）
3. ✅ 修复 Bloom 数据流（Combined 缓冲 + ToneMapping 读 Combined）与 Shadow 开关（灯光提交参考 EnableShadows）
4. ⬜ 完整动态：每帧重建 pass 图（UE5 RDG 风格）

## 完整动态（UE5 RDG 风格，后续）

### UE5 FRDGBuilder 核心
- **每帧构建**：`GraphBuilder.AddPass(name, params, lambda)` 注册 pass，pass 不是持久对象而是 lambda + 描述
- **虚拟资源**：`CreateTexture` 返回句柄，实际 GPU 分配延迟到 Execute 阶段
- 构建 → 依赖推导 → 调度执行 → 帧末销毁，每帧全新

### 当前引擎差距
| UE5 RDG | 当前引擎 |
|---------|----------|
| 每帧构建 pass 图 | 配置驱动重建（dirty 才重建）|
| pass = lambda + 描述 | pass = 持久类对象 |
| 虚拟资源（句柄每帧声明）| handle 持久（OnAttach）|
| 依赖构建时推导 | 拓扑排序每次 Execute（已有）|

### 渐进实施
1. **每帧重建 pass 对象**：OnUpdate 每帧调 `BuildRenderGraph`（去掉 dirty 标记），pass 条件出现（无点光不加 PointShadowPass 等）
2. **pass 对象池**：每帧 CreateScope 有分配开销 → 按类型复用 Scope（优化）
3. **虚拟资源**（后续）：handle 每帧声明，分配延迟到 Execute

### 收益
- pass 按场景状态条件出现（阴影、bloom 按需）
- 资源按需声明（省显存）
- 为并行调度（TaskGraph）铺路

## 关键点

- 拓扑排序已支持动态（每次 Execute 重新推导）
- 资源 handle 需在 Build 时同步创建/销毁（Bloom 关 → BloomA/B/C handle 无效）
- EditorLayer 持有 pass 的 Scope，重建时需重新 CreateScope + 连接 handle
