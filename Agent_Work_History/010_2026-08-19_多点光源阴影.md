# 多点光源阴影开发记录（Cubemap Array）

## 日期
2026-08-19

## 目标
在已有单点光源阴影（单 cubemap）基础上，扩展为**多点光源阴影**，采用 **GL_TEXTURE_CUBE_MAP_ARRAY（cubemap array）** 方案，每个点光源占用一层 cubemap（6 个 array layer），上限 8 盏。

---

## 一、架构决策

### 决策 1：使用 cubemap array 而非多个独立 cubemap
- **方案 A（采用）**：`GL_TEXTURE_CUBE_MAP_ARRAY`，一次绑定、按 layer 采样，是 UE/Unity 的做法
- 方案 B（弃用）：多个 `samplerCube` + if/else 判断，绑定多、采样多、扩展性差

### 决策 2：`MAX_SHADOW_LIGHTS` 统一为 8
- 方向光/聚光（`u_ShadowMatrices` + `u_ShadowMaps` 深度数组）与点光源（cubemap array）**共用** `ShadowIndex` 编号字段
- shader 内按 `type` 区分走哪套存储（`LIGHT_TYPE_POINT` → cubemap array，其他 → 矩阵数组）

### 决策 3：cubemap array 的 layer 映射
- 每个点光源占 **6 个连续 array layer**（`layer*6 .. layer*6+5`）
- **写入**：`glFramebufferTextureLayer(fbo, GL_COLOR_ATTACHMENT0, tex, 0, layer*6+face)`
- **采样**：`texture(u_PointShadowMaps, vec4(dir, layer))`，`layer` 是 cubemap 索引

## 三、关键 bug 及解决

| # | 现象 | 根因 | 解决 |
|---|------|------|------|
| 1 | 加阴影后点光源光照+阴影全失效 | `RenderPointShadowPass` 后纹理单元 0 被污染（`glBindTextureUnit(0, ...)`）| `Bind()` 里移除多余纹理绑定 |
| 2 | 只测点光源时崩溃 | `UploadUniformMat4Array` 收到空 vector，`values[0]` 越界 | 加空检查 |
| 3 | 点光源加阴影后 Lo 被乘成 0（光照消失）| 点阴影判断恒为「全阴影」| 深度 cubemap 内容异常 |
| 4 | cubemap array 深度图纯黑（FS 采样）| `glFramebufferTexture3D` 用 `GL_TEXTURE_CUBE_MAP_POSITIVE_X+face` 对 array 不适用，attach 未生效 | 改用 **`glFramebufferTextureLayer`**，target 语义正确 |
| 5 | 多点光源只有第一盏有阴影 | 非 bug，当时只启用了 1 个点光源实体；后续观察到侧向灯阴影需调高强度和调整观察角度 | 强度不足 + 观察角度导致 |

## 四、经验教训

1. **cubemap array 的 attach 必须用 `glFramebufferTextureLayer`**，不能用 `glFramebufferTexture3D` 的 cubemap face 写法（`GL_TEXTURE_CUBE_MAP_POSITIVE_X+face`）——后者对 array 不适用，attach 静默失败
2. **`MAX_SHADOW_LIGHTS` 影响多个纹理的 layer 数**（`u_ShadowMaps` 深度数组、`u_PointShadowMaps` cubemap array、`u_ShadowMatrices`、`u_PointShadowFarPlanes`），改一处要全局同步
3. **cubemap array 的「采样 layer」是 cubemap 索引，不是 array layer**；「写入 layer」是 array layer = cubemapIndex*6+face
4. **DSA 与传统 GL 混用**：`glNamedFramebufferRenderbuffer`（DSA）和 `glFramebufferTextureLayer`（传统，需 FBO 当前绑定）混用时要确认绑定时机
5. **侧向点光源的阴影容易被忽略**：阴影投影在背光面，需要提高强度 + 多角度观察才能确认
