## 本次排查的问题（重要经验）

### 1. sceneBounds ±1e30 → ortho z 巨大 → 深度精度丧失
**现象**：Cascade0 AABB z = ±1.5e30（天文数字）。
**根因**：`sceneMin/Max` 在主光提交处用 **ShadowCasters** 合并——但 **ShadowCasters 在后面的实体遍历才填充** → 主光算时为空 → sceneBounds = 初始值 `glm::vec3(1e30f)` → 模型合并把 ortho z 撑成 ±1e30 → 深度精度全无 → 阴影消失。
**修复**：主光分支从 registry **实时算场景 AABB**（`view<TransformComponent, PBRModelComponent>` + mesh AABB 世界变换），不依赖 ShadowCasters 填充时机。

### 2. lightView 距离太近 → 场景部分在光平面后方（光空间 z 正负混合）
**现象**：光空间 z 范围 [-101.9, 16.8]（有正有负）。
**根因**：`lightPos = camPos - lightDir * cascadeFar * 2`（只 34.4 远）→ Ground（100m）斜射下部分在光后方 → z 横跨正负。
**修复**：`lightPos = sceneCenter - lightDir * (sceneRadius * 2 + 100)`——光足够远，场景全在光前方（z 全负）。

### 3. glm::ortho 负 near/far → NDC 映射错乱（CLIP z 超界）
**现象**：原点光空间 z=-38.29 ∈ ortho z [-111.9, 26.8]，但 **NDC z=1.165 > 1**（在 far 外）。
**根因**：`glm::ortho` 期望 **near/far 是正 depth**（OpenGL 相机看 -Z）——传负 near → NDC 映射错乱。
**修复**：光空间 z 全负后 **正化 depth**：
```cpp
float nearDepth = -maxB.z;   // 最近 → 正 depth
float farDepth  = -minB.z;   // 最远 → 正 depth
glm::mat4 lightProj = glm::ortho(minB.x, maxB.x, minB.y, maxB.y, nearDepth, farDepth);
```

### 4. 调试打印用错索引
**NDC 打印用 `ShadowViewProjections[0]`** 应 `[shadowIndex]`（主光 push 起始索引）——场景有多个阴影光时 `[0]` 不是级联 0。**调试误导**。

## 调试方法论（本次磨出的）

1. **RenderDoc EID 分析**：确认 ShadowPass 渲了 3 层 Furina（298 万索引）、MainPass 绑 shadow map + 级联矩阵 + splits——**管线从上到下都对，问题在 shader/数学层**
2. **shader 三通道输出**（RGB = uv.x/uv.y/采样深度）——一次看全变换 + 深度图内容
3. **ctor 内打印 Origin NDC**（用刚算的矩阵）vs EditorLayer 打印——**分清真矩阵 vs 打印矩阵**
4. **打印 Origin 光空间 z vs ortho range**——发现数学矛盾（z 在范围内但 NDC 超界）→ 挖出 glm::ortho 负 near/far 问题

## 最终实现

- **ShadowMath**：`CascadeSplit` + `ComputeDirLightCascadeVP`（切片→光空间 AABB→ortho，lightPos 基于场景 + ortho 正化 depth）
- **EditorLayer**：主方向光 3 层级联（场景 AABB 从 registry 实时算），其他方向/聚光单层
- **Pass.h**：`CascadeSplits`（vec3）
- **MainPass**：上传 `u_CascadeSplits`
- **PBRShader**：按距离选级联（`layer = ShadowIndex + cascade`）+ 对应 `u_ShadowMatrices`/深度层
- **PerspectiveCamera**：fov/getter

- 远处（17-100m）级联 1/2 覆盖（无摩尔纹）
